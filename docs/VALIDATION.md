# Проверка библиотеки

Проверено локально 19 октября 2026: Windows 11, Temurin JDK 21.0.12.1, Maven Wrapper 3.9.11.
Код компилируется с `--release 17`; CI для JDK 17/21 подготовлен, но удалённый workflow
ещё не запускался. Весь Javadoc публичного API написан на английском.

Координаты локального релиза: `io.github.saqqqner:diagram-kiln:1.0.0`.
Классы и имя модуля используют `io.github.saqqqner.diagramkiln`.
Релизная сборка `clean install` прошла: 70 тестов, строгий Javadoc, форматирование
и отдельный Maven-потребитель версии 1.0.0. Все пять Java-примеров скомпилированы
с релизным JAR; сценарий на 30 узлов дополнительно запущен с ним.

## Сценарий около 30 объектов

`examples/ThirtyNodeDiagram.java` строит 30 обычных узлов, семь контейнеров двух уровней
и 32 связи: внутренние, межгрупповые, группа-группа, петля и параллельная связь.
Используются все три формы узлов, скругление, заливки и пунктирные переходы.

Результат одного локального запуска отдельного JVM-процесса:

| Показатель | Результат |
| --- | --- |
| Первый вызов toXml, включая инициализацию ELK | 1078,1 мс |
| Медиана пяти последующих вызовов | 26,5 мс |
| UTF-8 XML | 37 833 байта |
| Обычные узлы / контейнеры / связи | 30 / 7 / 32 |

Это измерение указанного примера на локальной машине, а не обещание времени для любого
графа. Направления, топология, количество связей и вложенность влияют на стоимость ELK.
JUnit-проверка контролирует число элементов, уникальность id, существование parent/source/target
и конечную геометрию. Файл результата: `examples/thirty-nodes.drawio`.

XML-модель открыта в draw.io: все 30 узлов и семь контейнеров отображаются, включая
межгрупповые переходы, петлю и параллельные связи. Снимок: `examples/thirty-nodes-preview.png`.
В этом графе размещение получилось вытянутым по вертикали; общий обзор требует уменьшения
масштаба. ELK не гарантирует компактное размещение произвольной топологии.

Для повторения после `package dependency:copy-dependencies -DincludeScope=runtime`:

```powershell
javac --release 17 -encoding UTF-8 -cp "target/diagram-kiln-1.0.0.jar;target/dependency/*" -d target/examples examples/ThirtyNodeDiagram.java
java -cp "target/examples;target/diagram-kiln-1.0.0.jar;target/dependency/*" ThirtyNodeDiagram
```

## Остальные проверки

- 70 unit/integration-тестов основного проекта: DSL, снимки, группы, стили, реальный ELK,
  XML, ошибочные данные и пользовательская геометрия.
- Отдельный Maven-потребитель проверяет фактический JAR и транзитивные runtime-зависимости.
- `doclint=all`, `failOnWarnings=true`, formatter validation.
- Плотные параллельные связи проверяют попадание в скруглённую границу при `arcSize`
  0, 12, 15, 35 и 100. Геометрия учитывает ограничение радиуса половиной меньшей стороны.
- Проверены все варианты `JumpStyle`, размеры стрелок/перемычек, скругление линий,
  сохранение маршрутов ELK и старые конструкторы стилей/настроек.
- DSL `LayoutOptions` проверен на реальном ELK: зазоры внутри слоя и между слоями,
  отступ контейнера с заголовком; дополнительно проверены снимки настроек и валидация.
- Независимое read-only ревью архитектуры, API, XML, тестов и упаковки не нашло замечаний.

Просмотр XML-модели в draw.io выполняется через Extras → Edit Diagram. Полный контейнер
mxfile дополнительно проверяется XML-парсером. Автоизмерение текста и оптимизация
пересечений подписей связей не входят в текущую версию.

## Визуальная проверка новых стилей и LayoutOptions

`examples/VisualStylesDiagram.java` запускается против собранного JAR и генерирует два стенда.
Оба импортированы через Edit Diagram в браузере draw.io 19 октября 2026 и проверены визуально:

- `examples/visual-layout.drawio`: реальный ELK, направление DOWN, узлы 180×60,
  зазоры 50/90, отступ групп 30. Видны разные скругления (12/45), внутренние переходы,
  связь внутренних узлов разных групп и отдельная синяя связь контейнеров.
  Снимок: `examples/visual-layout-preview.png`.
- `examples/visual-jumps.drawio`: одинаковые заданные координаты обеспечивают пересечения
  для сравнения NONE/ARC/GAP/SHARP. Видны дуга, разрыв и угловая перемычка, зелёные
  скруглённые изгибы (`arcSize=30`), разные размеры стрелок (2/12).
  Снимок: `examples/visual-jumps-preview.png`.

Второй стенд использует пользовательский LayoutEngine для гарантированных пересечений;
он проверяет отрисовку стилей в draw.io. Работу настроек реального ELK проверяет первый стенд
и автоматические тесты. Изменений реализации после просмотра не потребовалось.

## XML и #R

`DrawioFragmentTest` независимо распаковывает raw DEFLATE через JDK Inflater и проверяет
совпадение с исходным XML, включая вложенные группы, стили, кириллицу, emoji, буквальные `%20`,
проценты и плюсы. Дополнительно проверены пустая диаграмма, 120 узлов, заданная геометрия,
ошибочная геометрия и один вызов LayoutEngine на генерацию фрагмента.

`examples/DrawioFragmentExample.java` запущен с упакованным JAR после упрощения URI-кодирования:
XML — 2613 символов, фрагмент — 1252. Ссылка из `examples/fragment-example-url.txt` открыта непосредственно в
браузере draw.io без ручного импорта XML. Обе группы, связь и подписи `100% +`, `%20`, `<OK>`
и emoji отображаются корректно. Также проверены переносы строк и пунктуация `! ' ( ) ~ * ? # / = "`.
Снимок: `examples/fragment-example-preview.png`.

Чистая сборка `formatter:format clean install` прошла: 70 тестов, строгий английский Javadoc,
50 файлов Java в проверке форматирования и отдельный Maven-потребитель. Независимое ревью
реализации кодирования не выявило замечаний. Публикация не выполнялась.
